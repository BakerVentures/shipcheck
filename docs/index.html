shipcheck is a Claude Code plugin for React Native and Expo apps. It reads your project and store listing, checks them against the live App Store Review Guidelines and Google Play policies, and tells you the clause, the reviewer's likely wording, and the fix.

What it checks

The guideline corpus is fetched live and cached with a date and hash, so you're never checking against last year's rules. /shipcheck:refresh shows you what Apple changed since your last scan.

  • PrivacyRequired-reason API declarations for your app and every SDK in node_modules, NSUsageDescription strings pulled in by Expo modules, ATT prompt timing, App Privacy label consistency.
  • SubscriptionsPrice, period, and renewal disclosure on the paywall, restore purchases, intro-offer terms, and guideline 3.1.2 wording.
  • AccountsSign in with Apple when third-party login exists, account deletion when accounts exist, demo credentials in review notes.
  • MetadataPlaceholder text, dead URLs, screenshots that show features not in the build, references to other platforms or pricing, age rating mismatches.
  • BuildIcon dimensions and alpha, export compliance flag, dev-menu and Expo Go artifacts in production, minimum-functionality signals for guideline 4.2.
  • AndroidManifest permissions versus Data safety declarations, target API level, privacy policy link, closed-testing requirement, prominent-disclosure for runtime permissions.

Also runs without Claude Code

The deterministic half — everything except store-listing judgment — is a zero-dependency CLI, so it runs in CI or under any other agent.

git clone https://github.com/BakerVentures/shipcheck && shipcheck/bin/shipcheck scan . Exits 1 on a critical finding, so it gates a pipeline. 
# .github/workflows/shipcheck.yml
- uses: BakerVentures/shipcheck@v1
  with:
    fail-on: critical

The judgment checks — store listing, paywall disclosure, category rules, guideline 4.2 — need a model reading current guideline text, so those stay in the Claude Code plugin, where your own Claude does that work at no cost to us.

Already rejected?

Paste the Resolution Center message into /shipcheck:reply. It reads the cited guideline, checks what you've changed, and drafts the reply in the register reviewers actually respond to. If the fix isn't actually in the code yet, it says so and makes it — it won't draft a reply claiming something that isn't true.

Isn't there a free version of this?

Yes — several. The deterministic code and config checks are table stakes now and free everywhere, including in shipcheck's own free scan. What the free tools can't reach is your actual store listing: the description, screenshots, paywall copy, and demo account you're about to paste into App Store Connect, which is roughly half of what actually gets apps rejected. Questions

Does my code get uploaded anywhere?
No. The scan runs in your own Claude Code session. The only network calls are fetching Apple and Google's public policy pages and, if you buy a license, a key check that sends the key and plugin version and nothing else.
Does it guarantee approval?
No. It catches the rejections that come from the guidelines and from common React Native and Expo configuration mistakes. It can't run your app or predict a reviewer's mood.
Why React Native and Expo specifically?
Because that's where the config-level rejections cluster: transitive permission strings, SDK privacy manifests, Expo Go leftovers. Native Swift projects work too, with less depth.
Why not just ask Claude to review my app against the guidelines?
Because "the guidelines" in Claude's training data are however old the model's cutoff is, and Apple and Google change these pages constantly. shipcheck fetches the live pages, hashes them, and cites the clause off disk — /shipcheck:refresh shows you exactly what changed since your last scan. A citation in your report is text it actually fetched, not text a model remembered.
